## Key Insights
- 257 Python tests are NOT 1:1 portable; the parity goal is behavioral equivalence on a *user-facing* test matrix, not test-file translation.
- Cutover is a single PR: delete legacy + add docs. Reversible via revert.
- A side-by-side parity test is the strongest signal: same input URLs into v1.2.0 and v2.0.0 should produce equivalent file outputs (same id, similar size).

## Requirements

### Test layers
| Layer | Tooling | Coverage target |
|-------|---------|-----------------|
| Rust unit | `cargo test` | ≥80% on ported modules (url_parser, path_builder, retry, fb_resolver, config, classify, history) |
| Rust integration | `cargo test -- --include-ignored` with fake yt-dlp shim | engine smoke, channel listing, history import |
| Frontend unit | Vitest | stores, IPC wrappers, validators |
| E2E smoke | `@tauri-apps/cli` + Playwright | 5 critical paths |
| Parity | manual + scripted diff | v1.2.0 vs v2.0.0 outputs match |

### Critical E2E paths (Playwright)
1. Single TikTok URL → download → file lands at `<output>/tiktok/<uploader>/<id>_<title>.mp4` → History row appears.
2. Drag-drop a `.txt` of 3 mixed URLs → all 3 queued and complete.
3. Channel/Page tab → search a known TikTok profile → results stream → select 2 → download both.
4. History tab → search → filter by Facebook → right-click → Open folder.
5. Settings → change Quality to 720p → restart → setting preserved → download → file is 720p.

### Parity test harness (`scripts/parity-test.mjs`)
1. Reads a fixture file `tests/parity/fixtures.json` of 5-10 known-public URLs (TikTok + FB; pin video IDs).
2. Runs v1.2.0 build (PyInstaller artefact) against output dir A.
3. Runs v2.0.0 build against output dir B.
4. Diff: for each video_id, both outputs exist; sizes within ±5%; titles identical; folder shape identical.
5. Outputs report `tests/parity/report-<date>.md`.

## Risk Assessment
- **A user upgrading loses partially-completed downloads.** Document; partial files in old `downloads/` tree are still valid (filename scheme preserved).
- **CLI users blocked by removal.** Document yt-dlp.exe direct invocation in migration notes; the bundled `binaries/yt-dlp-x86_64-pc-windows-msvc.exe` is reachable from the install dir.
- **CI Windows runner cost / flake.** Use `windows-latest` GHA; pin actions/setup-rust + actions/setup-node versions; cache cargo + pnpm.
- **Parity script depends on live URLs that may break.** Use 5 stable TikTok hashtags or community-pinned videos; mark fixtures with "verified-on-{date}" to flag for refresh.
- **Documentation rot during phase 02-09 work.** Rewrite docs from scratch in this phase; do not attempt incremental updates earlier.

## Security
- E2E test credentials (cookie browser) only run in dev; CI uses `--cookies-from-browser none` (no auth).
- Release artefacts checksum'd; SHA256 published with the GitHub release.
- License compliance: yt-dlp (Unlicense), ffmpeg (LGPL or essentials build, document), Tauri (MIT/Apache-2), all Rust crates (audit `cargo deny check licenses`).
